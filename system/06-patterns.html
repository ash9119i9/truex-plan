6.1

Composition · grammar

A pattern is a sentence.

The primitives are words. A pattern puts them in an order that repeats: the answer before the work, the request above the composer, the shell around both. Six patterns carry the product — and none of them invents a new part.

Four rules
01
Arrange, never restyle.

A pattern may place, size and group primitives. It may not invent a colour, a type size or a corner.

02
Every control is a tx part.

If a pattern needs a new button, field or option row, the atom is missing from 05 — not added here.

03
The narrow twin is part of the pattern.

A pattern ships with its 390 px, 200% and keyboard form. The room folds; the meaning stays.

04
One recurring decision per pattern.

Answer first. Work folded. Request docked. Shell stable. Overlay one deep. If a pattern makes two decisions, it is two patterns.

ChunkingSix, not sixty.

A room is remembered as a handful of regions, not a list of controls. Patterns are the chunks.

DisclosureAnswer first.

The eye gets the claim before the evidence. The log opens only when verification is the job.

ConstancyNothing blocking moves.

A request that can scroll away is a request that will be missed. The dock keeps it in place.

RecognitionSearch, then act.

The palette shows what exists. It removes the memory tax of hidden commands and deep menus.

Composition is subtraction. Each pattern removes a decision from the next screen. The primitives supply the parts; the pattern supplies the order.

6.2

Pattern 01 · the turn

Answer first, evidence under it.

A turn is the unit of work: what you asked, what the agent answered, what it did and what it cost. The answer is read; the evidence is inspected. The work never pushes the answer down.

6.3

Pattern 02 · the work log

Evidence, folded.

Every turn keeps one log, folded under the answer. It is not a second narrative: one summary, one row per event, typed nodes and durations in mono. The log is opened to verify, not to read.

01
One fold.

The summary is the only always-visible line.

6.4

Pattern 03 · the request dock

It cannot scroll away.

A blocking request stops the turn, so it docks above the composer and keeps a placeholder in the stream. Four methods use one card: tool approval, question, secret and plan. One primary decision, one expiry, one audit row afterwards.

01Spatial constancy

The dock sits above the composer at every width. A blocking request cannot be scrolled away.

02One primary

Allow once, Send answer, Submit key, Approve plan. The widening grants and the exits are secondary or ghost.

03Always asks

Secrets and plans ignore the approval mode. A silent yes is never inferred for either.

04An audit, not a memory

After resolution the stream keeps one row with the decision, the actor and the reference.

A missed request costs the whole turn. The dock, the one primary and the countdown are cheaper than a re-run. The expiry is part of the decision, not a decoration.

6.5

Pattern 04 · the shell

A room that folds.

The shell is a rail, a main thread and an inspector, held by a topbar. It folds by its own width, not the page: 232 → 64 → 0 for the rail, 64 → 0 for the inspector. The thread, the composer and the primary request never leave.

6.6

Pattern 06 · the palette

Recognition over recall.

One input, grouped results, shortcuts you can see. The palette is how the product is driven without learning every surface. It floats over the room, one layer deep, and returns focus exactly where it left.

The keyboard contract
01
One input.

Typing filters label and keywords; no separate search mode.

02
Groups, not a list.

Go to, Actions, Agents. Three chunks beat one long column.

03
Destructive is never default.

Stop and delete live in a danger group and never take the first selection.

04
Focus returns.

Esc, scrim and Enter all return focus to the trigger.

Why it works

Recognition replaces recall: the command is visible before it is remembered.

Search beats a memorised path: one input instead of six clicks.

One layer of overlay: no palette inside a palette, no hidden state.

⌘K↑↓↵Esc

The palette is the shortest path to everything the screen already knows. If an action matters, it is findable here; if it is destructive, it is never the first answer.

6.7

Patterns · states & adaptation

The narrow twin keeps the meaning.

A pattern is finished only when it has a narrow twin: the same work at 390 px, at 200% text, on a keyboard and under reduced motion. The room folds; the answer, the dock, the composer and the primary decision stay.

What survives
  • The answer and its reading order.
  • The request dock and its one primary.
  • The composer, held or free.
  • The audit reference and the approval record in the log.
  • Focus return from every overlay.
  • The static twin under reduced motion.
What folds
  • Rail labels → numeric marks → nothing.
  • Session list and crew list.
  • Inspector rail → drawer → full-width drawer.
  • Palette width; request actions wrap.
  • Measures and secondary metadata.
  • Never the primary decision.
The contract at 200%

Container, not page. The shell uses its own width; text zoom folds it earlier instead of breaking it.

One primary. Request actions wrap; the allowed decision never loses rank.

Focus returns. Esc closes the inspector and palette; the trigger keeps the ring.

Motion yields. The countdown keeps its value; the spinner, shimmer, caret and drawer have static twins.

No separate mobile design. The narrow twin is the same contract at a smaller width: the same answer, the same dock, the same primary, the same return.
