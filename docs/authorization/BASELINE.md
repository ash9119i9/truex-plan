## Isolation changes

`platform/test/environment.ts` preserves operating-system plumbing and drops inherited application routing, mail/AWS credentials, proxies and Node injection flags. Each subprocess receives explicit fixture settings. `DOTENV_CONFIG_PATH` is forced to the operating-system null device; tenant/migration/purge scripts honor that override while keeping their original default dotenv path outside tests. The shared HTTP harness rejects a non-loopback runtime or deployment ARN. Deliberately mocked Bedrock tests inject their transport explicitly.

The environment regression launches a real child next to a hostile `.env` and verifies it cannot acquire routing or mail settings. This protects fixture isolation; it is not a blanket operating-system/network sandbox. Existing process-local tests that deliberately save/restore `process.env` retain that behavior.

## Baseline defects found and repaired

1. **MCP migration rewrote credentials and used a removed API.** Existing `migrate-mcp-scopes.test.ts` required scope/attachment/index migration with unchanged credentials and no encryption key. The old script still called removed `encryptSecret`, refused without a key and removed plain credential fields. The fix preserves every credential field and limits the operation to scopes/attachments/indexes. The existing regression failed before and passes afterward against real standalone Mongo. Credential isolation/migration into the future broker remains a separate required feature.
2. **Provisioning error-text drift.** `provision-demo default` correctly rejected the implicit default tenant but its message no longer matched the established safety test. The CLI now says `public signup tenant cannot be the implicit "default" tenant`; rejection behavior is unchanged. The test's subprocess environment is now isolated too.
3. **Filesystem timestamp precision.** The sweeper stress test compared stored filesystem timestamps with a JavaScript Date exactly. The actual filesystem returned a value 0.001 ms lower. The repaired assertion compares the actual stored pre-sweep timestamp exactly with the post-sweep timestamp, proving the intended no-rewrite property without a loose tolerance. Runtime sweep/deletion code is unchanged.

## A06 tenant storage boundary (2026-10-12)

OIDC Stores now capture enterprise mode at construction and require an unexpired authorization context plus an immutable tenant reference minted by the same Store before selecting tenant databases or building their indexes. Missing context, forged/cloned/cross-Store references, mismatched tenant/generation and expired credentials produce zero database selections in the replica-set test. Concurrent authenticated fixture contexts read only their own tenant's records. Catalog identity operations before tenant selection remain available. Enterprise startup no longer creates resource indexes through an implicit default database.

Enterprise tenant resolution reads the current registry rather than the legacy cache and never synthesizes an unregistered default tenant. It rejects missing/corrupt generations, system/catalog/default aliases and invalid database mappings. Final adversarial review tightened database names to lowercase ASCII to reject case aliases. The [storage contract](STORAGE_CONTEXT_CONTRACT.md) explains the trusted control-plane interfaces, retained Mongo handles, live policy requirements and safe rollback boundary. This is a structural guard, not an engine permission decision or a revocation-delivery proof.
