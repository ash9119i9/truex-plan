# Truex runtime boundary

Truex uses the pinned codex-rs engine while preserving its useful conversation
features. The policy restricts host access and internal implementation disclosure;
it is not a reduced chat-only runtime.

## Available features

- Streaming answers and the engine/provider's thinking output, including separate
  summary and text streams. Thinking is displayed in the expandable Thinking panel
  and included in live reconnect snapshots when retained by the adapter.
- Plans, response timings, first-output latency, stream duration and total duration.
  Timings survive service restarts through the existing persistence pipeline.
- Stop, follow-up/steering, history, replay and same-owner resume.
- Fork, compact, goals, model/reasoning settings and archive. Browser parameters are
  allowlisted per operation; these controls cannot change workspace, permissions,
  instructions, runtime configuration or arbitrary history. Forks retain the
  parent's provider configuration and get a new managed work directory.
- HTTP MCP tools and connector configuration in the Connected tools panel.
- Explicitly enabled collaboration, goals, normal-mode clarification and live web
  search (configurable per model profile). Web search remains subject to provider
  support. Apps/plugins still depend on the pinned engine's authentication support.
- Adapter-owned document upload, extraction and generation through validated
  dynamic tools. Files are confined to managed conversation storage; no host paths
  or shell access are granted. See [assistant capabilities](ASSISTANT_CAPABILITIES.md).

## Restricted features and data

- Thread creation and every user turn start select `environments: []`. The pinned
  engine consequently does not register shell, patch or local-image handlers.
  Spawned agents inherit the parent's environment selections. Shell flags, local
  permission requests and command hooks remain disabled.
- Work directories are generated by the adapter, never selected from a browser
  parameter. Project instruction loading and environment-context injection are
  disabled. The child receives a small environment allowlist, with HOME and
  CODEX_HOME pointing to the dedicated runtime home.
- Local stdio connectors and automatic skill dependency installation remain
  unavailable because they can execute host commands. Host a connector separately
  and configure its HTTP endpoint instead.
- Shell commands/output, local file diffs, paths, repository structure, credential
  configuration, raw turn items and unknown runtime events are not forwarded to
  the browser. Thinking, plans and timing fields have explicit public projections;
  this is not a blanket suppression of runtime activity.
- The product identifies itself as Truex. Runtime identity, diagnostic payloads,
  raw schema browsing and general configuration RPCs remain internal. Assistant
  instructions prohibit volunteering implementation details; authorized business
  data is sourced from connectors, not by searching the application repository.
- Business clarification questions remain available. Host permission approvals
  and unsupported runtime approval/elicitation requests are denied; this version
  does not implement a separate approval workflow for every connector action.

## Existing conversations and deployment

Sessions carry `runtimePolicyVersion: 1`. Older pre-policy sessions remain stored,
are excluded from chat listings, and cannot be opened, resumed or streamed through
chat. Their history may already contain implementation details. Do not mark those
records as current merely to reopen them. Sessions created under version 1 remain
usable with the restored presentation and conversation features.

Refresh the browser after upgrading. Development watchers reload source; production
processes need to be restarted after building. Preserve the entire runtime-home
volume, including `business-v1`, for restart recovery.

## Verification and limits

Tests run the real pinned binary with simulated model/MCP endpoints. They force
local tool calls and check that a private canary is neither read nor changed;
verify that collaboration tools remain advertised; test restricted fork parameters
and a usable fork with no local tools; verify HTTP MCP, provider isolation and
restart/resume; and check public thinking/plan/timing projections and reconnect
behavior. No live business system is contacted by these tests.

The tool policy is not an OS/container filesystem sandbox for a compromised runtime
process. HTTP connector services must enforce their own access scope. Keep
agent-core private. Authentication and tenant authorization remain separate
requirements before public or multi-tenant deployment.
