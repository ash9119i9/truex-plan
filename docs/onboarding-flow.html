How people get into Truex, and what they do there

Everyone signs in with a Gmail account, but only after someone invites them. Tenants hold the people, chats and connected tools. This page covers the full path from an empty platform to a team working in it, then the everyday flows.

Roles

Three kinds of people

Platform operator

Admin dashboard · admin.<domain>
  • Creates tenants
  • Sets tenant settings: status, allowed models and skills, chat visibility
  • Invites each tenant's first admin
Can't see any tenant's chats, agents or tools unless invited into that tenant like anyone else.

Tenant admin

Main app · Members, MCP settings
  • Invites users and other admins
  • Changes roles, removes members
  • Adds shared (tenant) MCP servers and attaches them to agents
  • Can read every chat in the tenant
Can't write into someone else's chat.

User

Main app
  • Creates agents and chats
  • Connects personal MCP servers that only load in their own chats
  • Uses the tenant's shared MCP servers
Sees other people's chats only when the tenant allows it, and then read-only.

Operators come from the PLATFORM_OPERATOR_EMAILS setting (default ashokjoe2001@gmail.com). Roles belong to a membership, so one person can be an admin in one tenant and a user in another.

Onboarding

From an empty platform to a working team

  1. OperatorAdmin dashboard

    Operator signs in to the dashboard

    Sign in with Google. An operator email needs no invite here, because nothing exists yet to invite from. Any other email is refused.

  2. OperatorAdmin dashboard

    Create a tenant

    Give it an id and a name, then pick allowed models, skills and chat visibility. Creating a tenant adds no members.

  3. OperatorAdmin dashboard

    Invite the first admin

    Enter a Gmail address. The invite is always admin and expires in 7 days. No email is sent yet, so use "Copy sign-in link" and share it by hand.

  4. Tenant adminMain app

    The admin signs in and lands in the tenant

    The first sign-in finds the pending invite, creates the account and membership, and marks the invite accepted.

  5. Tenant adminMain app · Members

    Invite the team

    From Members, invite each Gmail address as user or admin. Pending invites can be revoked. Optionally add shared MCP servers and attach them to agents.

  6. UserMain app

    Users sign in and start working

    Each user signs in with the invited Gmail. People in one tenant land straight in it. People in several pick one first.

Everyday use

Common flows inside a tenant

Start a chat

  1. Pick an agent and send a message.
  2. The chat is owned by you from then on.
  3. Only you can send messages, approve tools or change its settings.
Turns run with the owner's personal MCP credentials, which is why only the owner can write.

Connect your own tool

  1. Open MCP settings, then Your servers.
  2. Add a name, an HTTPS URL and an optional key.
  3. Attach it to one or more agents.
  4. It loads in your chats with those agents, and nobody else's.
Names use letters, digits, hyphens and single underscores. A name already used by a tenant server is refused.

Share a tool with the tenant

  1. A tenant admin opens MCP settings, then Tenant servers.
  2. Adds the server with one shared key.
  3. Attaches it to agents.
  4. Every chat with those agents gets it.
Users see that it exists and which agents use it, but never the key.

Change a tool mid-chat

  1. Attach, detach or rotate a key in MCP settings.
  2. Open chats pick up the change on their next turn.
  3. A turn that's already running finishes with the old setup.

Switch tenant

  1. Open the user menu, then Switch tenant.
  2. Pick another tenant you belong to.
  3. You get a fresh session in that tenant. Chats and tools from the other tenant don't follow.

Sign out

  1. Open the user menu, then Sign out.
  2. The session is deleted on the server right away.
Visibility

Who can open a chat

Set per tenant by the operator: all (the default) or own.

Hidden chats look like they don't exist: they're left out of the list, and opening a link to one returns "not found". Under own, projects are personal folders too.

Sessions

How long you stay signed in

7 daysMain app, idle limit
30 daysMain app, hard limit
8 hoursAdmin dashboard, hard limit

You get a new session on every sign-in and tenant switch. Access ends right away when an account or tenant is disabled, or a membership is removed.

Offboarding

Removing people and tenants

Remove a member

  1. A tenant admin opens Members and removes the person.
  2. Their sessions in this tenant end.
  3. Their personal MCP servers are deleted without anyone reading them.
The last admin of a tenant can't be removed or demoted. Other tenants they belong to are unaffected.

Disable a tenant

  1. The operator sets the tenant's status to disabled.
  2. Everyone's next request in that tenant fails, within about 5 seconds.
  3. Sign-in skips it, and tenant_disabled is shown when it was the only one.
