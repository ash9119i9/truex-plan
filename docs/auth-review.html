Authorization

Roles live on the membership and are admin or user. The rules for chats and project folders sit in access.ts:

CallerTenant shows all chatsTenant shows own chats only
OwnerRead and changeRead and change
Tenant adminRead onlyRead only
Other userRead onlyHidden (404)
  • Every session route checked goes through sessionFor(id, "read" | "write"), and lists filter by owner inside the database query.
  • Tenant MCP servers need a tenant admin. User MCP servers belong to one person; anyone else gets a 404.
  • Any member can create agents, by design for the alpha.

Gaps

  • highagent-core accepts any caller

    It's a plain Express app with no shared secret, so routes like /threads/:id/documents serve anyone who can reach them. That's safe today only because it listens on 127.0.0.1. Once agent-core runs on its own host, anyone on that network can read any thread. Confirmed.

  • mediumRate limits live in memory

    Counts reset on restart and each platform instance counts on its own. Admin login has no lockout after repeated failures. Confirmed.

  • mediumOpen live streams aren't rechecked

    The chat event stream is authorized once when it opens. A removed member keeps getting updates until it disconnects. Inferred.

  • lowagent-core health check shows internals

    /healthz returns the Codex home path, the pinned revision and the thread count. It only matters if agent-core is exposed. Confirmed.

  • lowCoarse roles, no audit log

    No per-agent edit or delete rights and no record of admin actions. Fine for the alpha; worth planning before more teams join.

  • openFrontend has no auth yet

    No sign-in pages, no redirect to login when a session expires, and admin-only controls aren't hidden from regular users. Planned to follow your designs.

Plan

  1. Secure agent-core. Require a shared secret on every platform-to-agent-core call, following the MODEL_GATEWAY_SECRET pattern, and block direct network access. Trim /healthz to booleans.
  2. Turn on Google mode.
    • Create a Google OAuth client with redirect URI ${APP_PUBLIC_URL}/auth/google/callback.
    • Set AUTH_MODE=google, GOOGLE_CLIENT_ID, GOOGLE_CLIENT_SECRET, ADMIN_PASSWORD_HASH (from npm run admin -- hash-password), RESEND_API_KEY with a verified sending domain, TRUST_PROXY, and MCP_ENCRYPTION_KEY.
    • Run migrate:mcp-scopes so the qlik and btp MCPs load again.
  3. Harden. Move rate limits into Mongo, add an admin login lockout, and recheck membership on open event streams.
  4. Build the frontend. Login, invite acceptance, tenant picker, logout, redirect on 401, role-based hiding, and the admin dashboard, following truex-design-spec.html.
  5. Later. Per-agent permissions, a Members panel for tenant admins, and an audit log of admin actions.
