truex design, locked for build

The exact visual spec for the truex agents UI, taken from the locked prototype (index.html and app.tsx on branch v2). Every value here comes from source and cites a line. Build to these numbers. If something is not covered, the source file is the tiebreaker.

How to use this spec

  • Tokens first. Paste the appendix token block into the main app as is. Components must use tokens, never literal hex, except for the few documented fixed colors (badge, sticky note, celebrate scrim).
  • Theme. Light is the default. Dark applies from prefers-color-scheme: dark unless <html data-theme="light"> is set, and always when data-theme="dark" is set.
  • Units. All sizes are CSS px at 1x. Durations are seconds as written in the CSS.
  • States. Every interactive element lists hover, focus-visible, active and disabled where they exist. Anything not listed has no special state.
  • Motion. Everything must respect prefers-reduced-motion: reduce (durations drop to 0ms).

Theme mechanism

useTheme() app.tsx:230–240 reads localStorage["truex-theme"] (default ""). When the value is non-empty it sets <html data-theme="light|dark">; when empty it removes the attribute, so the system prefers-color-scheme media block decides. The value is written back to localStorage on every change; storage access is wrapped in try/catch. Resolved theme: isDark = theme === "dark" || (!theme && matchMedia("(prefers-color-scheme: dark)").matches). The toggle always writes an explicit value: setTheme(isDark ? "light" : "dark"), so after the first toggle the system preference no longer applies.

Shading: tone(hex, amt)

const tone = (hex: string, amt: number) => {
  const n = parseInt(hex.slice(1), 16), t = amt < 0 ? 0 : 255, k = Math.abs(amt);
  const ch = (sh: number) => Math.round(((n >> sh) & 255) + (t - ((n >> sh) & 255)) * k).toString(16).padStart(2, "0");
  return "#" + ch(16) + ch(8) + ch(0);
};

Caption ink: inkOn(hex)

const inkOn = (hex: string) => {
  const n = parseInt(hex.slice(1), 16), c = (s: number) => ((n >> s) & 255) / 255;
  return .2126 * c(16) + .7152 * c(8) + .0722 * c(0) < .45 ? "#FFFFFF" : "#1F2A30";

Drag physics

On pointerdown the lanyard captures the pointer and records len = current strap offsetHeight (fallback 92) and r = max(40, clientY − lanyard.top) (grab distance below the anchor). Pointer move sets (x, y) = offset from the down point. Each render while dragging app.tsx:862-871:

dx = 260 * tanh(x / 320)                    // sideways: soft limit ±260px
reach  = hypot(dx, r + dy)
h      = max(len * .75, len + reach - r)    // strap stretches, never below 75% of rest
rotate = -atan2(dx, r + dy) in degrees      // whole lanyard pivots at top centre
width  = clamp(24 * sqrt(len / h), 16, 24)  // strap thins as it stretches

Rotation is applied to .lanyard, height/width to the strap. Pointerup/cancel clears drag; transitions (.7s spring) return rotation and strap to rest and the sway resumes.
