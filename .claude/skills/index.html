Skills: what to use, and when

A skill is a saved set of instructions for the AI coding agent. Instead of explaining how we plan, build, test and review every time, you pick the right skill and the agent follows our way of working.

How to use one

In Claude Code, type / and the skill name, for example /truex-build. Most skills also start on their own when you describe the job ("fix this bug", "review my change").

Use only what the change needs

A one-line fix doesn't need an idea session. Pick the steps that fit the size of the work. The quick picks below show where to start.

You stay in charge

Skills that write tests show you a list first and wait for your OK. No skill commits or pushes code unless you ask.

The usual order

Most work moves left to right. Skip the steps your change doesn't need.

  1. Ideamake it clear
  2. Plansplit into tasks
  3. Buildone task at a time
  4. Checktry to break it
  5. Reviewsecond pair of eyes

Something broke at any step? Use /truex-debugging-and-error-recovery, then go back to where you were.

Not sure where to start?

Find your situation. Every path ends with checking and review.

I'm fixing a bug

truex-debugging-and-error-recovery → truex-build (a test that shows the bug first) → truex-harden → truex-code-review-and-quality

I'm making a small change

truex-build → truex-harden → truex-code-review-and-quality

I'm building a feature

truex-planning-and-task-breakdown → truex-build for each task → truex-harden → truex-code-review-and-quality

I have a big or fuzzy idea

truex-idea-refine → truex-planning-and-task-breakdown → then the same as a feature

Add these only when your change calls for them: truex-frontend and truex-browser-testing-with-devtools for screen changes, truex-backend-performance for slow or busy server code, truex-observability-and-instrumentation for new endpoints or background work, truex-secure for anything touching logins, workspaces, tokens, connectors or uploads.

All skills

Fourteen skills, grouped by when you'd reach for them. Every skill name starts with truex-, so type /truex- to see them all. The ones marked New were written from scratch for this project; the rest are adapted to it.

Each skill, what it does, and when to use it
Skill What it does Use it when How it starts
1 · Shape the work
truex-idea-refineSaves to docs/ideas/ Turns a rough idea into a clear one: the problem, a few options, the one we pick, and what we're not doing. You have an idea but it's still fuzzy, or the feature is big. Auto or /type
truex-planning-and-task-breakdownSaves to tasks/ Splits the work into small tasks, each with a simple way to check it's done. Gives you a plan and a todo list. The work will take more than one sitting, or touches several parts of the app. Auto or /type
2 · Build it
truex-buildNew Builds one task from the todo list: writes the test first, then the code, then stops so you can look. Never commits. You have a todo list and want the next task done. Auto or /type
truex-test-driven-development The habit behind building: write a test that fails, then make it pass. For bugs, first write a test that shows the bug. Any time code changes what the app does, including bug fixes. Auto or /type
truex-frontendNew Our rules for screens in frontend/: keep the chat smooth while replies stream, keep pages light, and make them work with a keyboard and screen reader. You change anything in frontend/, or the chat feels slow or jumpy. Auto or /type
3 · Check it
truex-hardenNew Tries to break what you built and finds the cases your tests missed. Shows you a list first and writes only the tests you approve. A task or feature is built and you want to know what can go wrong. Auto or /type
truex-browser-testing-with-devtoolsNeeds Chrome DevTools connected (one-time setup) Opens the app in Chrome and checks what people actually see: the page, errors, network calls and speed. You changed something visible in the app. Auto or /type
truex-backend-performance Measures where the server is slow, fixes it, and shows before-and-after numbers. Something on the server is slow, or you're changing a busy path such as chat streaming, database queries or the model gateway. Auto or /type
truex-observability-and-instrumentation Adds the logs and numbers that let us see what a feature is doing once it's live. You add a new endpoint, background job, retry, or call to another service. Auto or /type
truex-code-review-and-quality A careful second look at a change: is it correct, easy to read, safe and fast enough. Before you merge anything. Auto or /type
4 · Fix problems
truex-debugging-and-error-recovery Finds the real cause when something breaks, instead of guessing at fixes. A test, the build or the app fails, at any step. Auto or /type
5 · Security (you choose these)
truex-secureNew Tries to get past Truex's protections: one workspace seeing another's data, misused tokens, or tricking the AI through a tool's output. Shows a list first. Your change touches login, workspace data, tokens, connectors, uploads, or AI output shown on screen. Only when you type it
truex-security-and-hardening A general safe-coding checklist: handle user input, passwords and secrets the safe way. You're writing code that takes user input or talks to outside services. Auto or /type
truex-security-audit A full security review of a whole area, with a written report. Before a big release, or when someone asks for an audit. Auto or /type

Auto or /type: the agent may pick it up on its own when your request matches, or you can start it with /name. Only when you type it: the agent never starts it by itself.

Three things to remember

  • All skills work on the new stack: frontend, platform-next, runtime-adapter and model-gateway.
  • When a skill shows you a list of tests or findings, read it before saying OK. That's where you decide what matters.
  • Commits and pull requests are always your call.
Skills live in .claude/skills/, one folder each. To change how a skill behaves, edit its SKILL.md and commit it so the whole team gets the update.
